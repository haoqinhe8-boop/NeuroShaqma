## 根因（两条，都是我的设计问题）

1. **"化验"太糙**：我用**单步 Δ** 去分类"死/漂移/异常值"，还依赖脊椎给的定位通道号：
   - 越界判断（`s<0 or s>50`）抢在前面 → **卡死（恒 5.0）被误判成异常值**；
   - 定位通道号一旦偏一路（模型耦合导致残差最大出现在邻通道）→ 分类必然错；
   - 动作/硬件类我直接按"comp==9 → 动作错位，否则硬件"拍死 → **四种全判成动作错位**。
   正解：**真做探针**——对每个候选通道分别发 3 步"前进"，逐个测它的 Δ：
   Δ≈0 → 死；Δ 有值但与模型预测**恒定偏差** → 漂移；读数越界 → 异常值。
   动作类用专门探针：命令前进看实际位移（=0 → 电机）；命令转向看 dyaw 符号（反 → 映射错位）；
   **看"测距变了但 dpos=0" → 编码器断线**（这条能区分出来，是我漏掉的判据）。
2. **★ 免疫层顺手揭穿了一个更严重的问题**：脊椎（③）里那个"**屏蔽坏通道**"的修复，
   **从来没有被复测验证过**——脊椎只检查了"修复消息的措辞"，没检查惊讶度是否真的回落。
   免疫层一做复测就发现：**屏蔽之后复测不通过**（2/4）。→ **脊椎的 ④ 判据是个"假绿"的隐患**，
   必须补上"修复后复测"这一步（正解：屏蔽的同时，要让世界模型**重拟合**一遍，否则旧权重仍然
   依赖被污染的那一路输入）。

## 下一步（一次做对）

1. **探针化化验**：每个候选通道单独探（多步、分别测），别用单步 Δ 猜；
